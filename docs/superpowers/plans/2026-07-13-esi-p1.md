# `@dwk/esi` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@dwk/esi`, a new cross-standard reusable lib that resolves
`<esi:include>`/`<esi:comment>`/`<esi:remove>` markup in a `Response` body via
a streaming transform, fetching fragments concurrently through
`@dwk/safe-fetch`. See
[`docs/superpowers/specs/2026-07-13-esi-design.md`](../specs/2026-07-13-esi-design.md)
for the full design rationale — this plan implements that design; don't
re-derive decisions already made there.

**Architecture:** New package at `packages/esi/` (pure over Fetch/Streams
APIs, no Workers bindings, Node-testable — same tier as `@dwk/safe-fetch`).
Depends on `@dwk/log` and `@dwk/safe-fetch` (`workspace:*`). No existing
package is migrated or modified beyond `CLAUDE.md`'s taxonomy list — this is
net-new, not an extraction.

**Tech Stack:** TypeScript (strict), Vitest (Node environment), pnpm
workspaces, Changesets (pre mode, tag `beta`).

## Global Constraints

- ESM-only, `"sideEffects": false`, exact-pinned deps, `workspace:*` for
  internal deps — see `CLAUDE.md` "Per-package layout & conventions."
- `strict` TypeScript via `tsconfig.base.json`; `import type` for type-only
  imports; ESLint flags unused vars unless prefixed `_`.
- Formatting: Prettier (semicolons, double quotes, trailing commas `all`,
  80-column width). Run `pnpm format` before committing each task; CI runs
  `pnpm format:check`.
- `index.ts` carries a doc comment stating the package's role and a `@see`
  pointer to the design doc (this package has no `spec/packages/esi.md`,
  per the design doc's release-bookkeeping section).
- Every task leaves `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, and
  `pnpm build` green for at least the packages it touches (final task runs
  the full suite).
- Commit after every task (never batch two tasks into one commit).
- No consumer package is touched in this plan — `@dwk/esi` ships standalone,
  matching the "general-purpose, no consumer chosen yet" scoping from #247.

### Task 2: Tokenizer — recognize ESI tags in a text stream

**Files:**

- Create: `packages/esi/src/tokenize.ts`, `packages/esi/src/tokenize.test.ts`

**Interfaces:**

- Consumes: nothing (pure string/array logic).
- Produces: a token model and an incremental tokenizer, e.g.:

  ```ts
  export type EsiToken =
    | { readonly kind: "text"; readonly value: string }
    | {
        readonly kind: "include";
        readonly src: string;
        readonly alt?: string;
        readonly onerror?: "continue";
      }
    | { readonly kind: "remove-block"; readonly raw: string }; // esi:comment
  // is consumed and dropped by the tokenizer itself — it never becomes a
  // token, since it never contributes to output either way.

  /**
   * Incremental tokenizer: feed it chunks of decoded text via `push`, get
   * back any tokens that are now fully resolved (i.e. not mid-tag). Call
   * `flush()` at end-of-stream to emit any trailing plain text (an
   * unterminated `<esi:...` tag at end-of-stream degrades to literal text,
   * never throws).
   */
  export class EsiTokenizer {
    push(chunk: string): EsiToken[];
    flush(): EsiToken[];
  }
  ```

- [ ] **Step 1:** Write failing tests: plain text passthrough; a single
      self-closing `<esi:include src="..."/>`; `alt`/`onerror` attribute
      variants and attribute-order independence; `<esi:comment text="..."/>`
      dropped entirely; `<esi:remove>...</esi:remove>` block dropped entirely
      including nested plain HTML inside it; a tag's `<`...`>` split across two
      separate `push()` calls (must still tokenize correctly, matching the
      reference implementation's chunk-boundary problem); malformed/unknown
      `<esi:...>` markup degrading to literal passthrough text rather than
      throwing; an unterminated tag at end-of-stream flushed as literal text;
      an unclosed `<esi:` prefix followed by more than the buffer cap (e.g.
      8 KB) of text flushes the buffered bytes as a literal `text` token and
      resumes normal scanning, instead of buffering unboundedly waiting for a
      `>` that never arrives.
- [ ] **Step 2:** Run `pnpm test --project @dwk/esi` — confirm failure
      (module doesn't exist).
- [ ] **Step 3:** Implement `tokenize.ts`. Internally: buffer incoming text;
      scan for `<esi:` start markers; once a complete tag (up to the matching
      `/>` for self-closing tags, or the matching `</esi:remove>` close tag for
      the block form) is available in the buffer, emit it as a token and any
      preceding plain text as a `text` token; text with no `<esi:` in it at all
      passes straight through without buffering (only text following an
      unresolved `<esi:` prefix is held back, same as the reference
      implementation's approach but tag-aware instead of a blind `<`/`>` split,
      and capped at a maximum buffered size — e.g. 8 KB — past which the
      buffer flushes as literal text rather than growing unboundedly on a
      malformed or unclosed tag).
- [ ] **Step 4:** Run tests — confirm pass.
- [ ] **Step 5:** Commit: `feat(esi): add ESI tag tokenizer`.

### Task 3: Fragment fetcher — resolve one `include` token

**Files:**

- Create: `packages/esi/src/fragment.ts`,
  `packages/esi/src/fragment.test.ts`

**Interfaces:**

- Consumes: `EsiToken` (`kind: "include"`) from Task 2; `safeFetch`,
  `readBodyCapped`, `MAX_BODY_BYTES`, `FetchLike`, `SafeFetchOptions`,
  `SsrfError` from `@dwk/safe-fetch`; `Logger`/`Metrics`/`noopLogger`/
  `noopMetrics` from `@dwk/log`.
- Produces:

  ```ts
  export interface FragmentFetchOptions {
    /** Base URL to resolve a relative src/alt against before validating it
     *  (`new URL(src, baseUrl)`) — see the design doc's API section. */
    readonly baseUrl?: string;
    readonly fetch?: FetchLike;
    readonly safeFetchOptions?: SafeFetchOptions;
    readonly maxFragmentBytes?: number;
    readonly logger?: Logger;
    readonly metrics?: Metrics;
  }

  /** Resolves an include token to its spliced-in text. Never throws — a
   *  failure of any kind resolves to "" per the design doc's onerror/alt
   *  rules, after trying `alt` when applicable. */
  export async function resolveFragment(
    token: Extract<EsiToken, { kind: "include" }>,
    options?: FragmentFetchOptions,
  ): Promise<string>;
  ```

- [ ] **Step 1:** Write failing tests: successful fetch splices the body
      text in; a non-2xx or thrown fetch with `onerror="continue"` resolves to
      `""` and logs at `debug`; a failure with `alt` set (no `onerror`) retries
      against `alt` once, resolving to the `alt` body on success or `""` (logged
      at `warn`) if `alt` also fails; a failure with neither `onerror` nor `alt`
      resolves to `""` logged at `warn`; a fragment body over
      `maxFragmentBytes` resolves to `""` (via `readBodyCapped` returning
      `null`); an `SsrfError` from `safeFetch` is caught the same as any other
      fetch failure (never propagates out of `resolveFragment`); a relative
      `src` resolves against `options.baseUrl` before being passed to
      `safeFetch` (and a relative `src` with no `baseUrl` configured is treated
      as a failure — resolves to `""` via the normal onerror/alt rules, not a
      thrown error, since `assertPublicUrl` can't parse a relative URL).
- [ ] **Step 2:** Run tests — confirm failure.
- [ ] **Step 3:** Implement `fragment.ts` per the design doc's error-handling
      table (§ "Supported markup").
- [ ] **Step 4:** Run tests — confirm pass.
- [ ] **Step 5:** Commit: `feat(esi): add fragment resolver`.

### Task 4: Streaming transform — wire tokenizer + fragment resolver into a `TransformStream`

**Files:**

- Create: `packages/esi/src/transform.ts`,
  `packages/esi/src/transform.test.ts`

**Interfaces:**

- Consumes: `EsiTokenizer` (Task 2), `resolveFragment` (Task 3).
- Produces:

  ```ts
  export interface EsiTransformOptions extends FragmentFetchOptions {
    readonly maxIncludes?: number; // default 50
    readonly concurrency?: number; // default 6
  }

  /** A TransformStream<Uint8Array, Uint8Array> that resolves ESI markup in
   *  the byte stream passing through it, preserving text order. */
  export function createEsiTransformStream(
    options?: EsiTransformOptions,
  ): TransformStream<Uint8Array, Uint8Array>;
  ```

- [ ] **Step 1:** Write failing tests (drive the `TransformStream` directly
      via its writer/reader, decoding output with `TextDecoder`): a response
      with two independent `<esi:include>`s resolves both, output order
      preserved even if the second fragment's fetch resolves before the first's
      (use a fetch stub with staggered `setTimeout`/deferred promises to prove
      ordering isn't fetch-completion-order); more than `maxIncludes` tags —
      extras drop with a `warn` log and empty splice, without affecting earlier
      ones; more than `concurrency` concurrent fragments — assert peak
      concurrent in-flight count never exceeds the configured value (fetch stub
      tracks a running counter); a multi-byte UTF-8 character (e.g. an emoji)
      whose encoded bytes are split across two written chunks decodes
      correctly (proves the transform's `TextDecoder` is a single reused
      instance, not one per chunk); a large chunked input where `<esi:include>`
      arrives split across two written chunks resolves correctly (exercises
      Task 2's chunk-boundary handling through the full stream, not just the
      tokenizer in isolation).
- [ ] **Step 2:** Run tests — confirm failure.
- [ ] **Step 3:** Implement `transform.ts`. A `TransformStream` that
      constructs **one** `TextDecoder({ stream: true })` instance up front
      (not per chunk — `stream: true` carries a partial trailing multi-byte
      UTF-8 sequence forward internally, which only works if the same
      instance sees every chunk in order; a fresh decoder per chunk would
      corrupt any character split across a chunk boundary) and reuses it
      inside `transform(chunk, controller)` to decode each chunk, feeding the
      decoded text to an `EsiTokenizer`. For each resulting token:
      `text`/`remove-block` tokens enqueue (or drop) synchronously; `include`
      tokens are handed to a small internal scheduler bounded by `concurrency`
      that preserves emission order (e.g. a queue of promises awaited in
      arrival order, each racing against the `concurrency` semaphore
      internally) — encode resolved fragment text back to bytes before
      enqueueing. `flush(controller)` calls the tokenizer's `flush()` for any
      trailing text.
- [ ] **Step 4:** Run tests — confirm pass.
- [ ] **Step 5:** Commit: `feat(esi): add streaming ESI transform`.

### Task 5: `processEsi` — the public `Response` wrapper + content-type gate

**Files:**

- Create: `packages/esi/src/esi.ts`, `packages/esi/src/esi.test.ts`,
  `packages/esi/src/index.ts`

**Interfaces:**

- Consumes: `createEsiTransformStream` (Task 4).
- Produces (package's full public surface, re-exported from `index.ts`):

  ```ts
  export interface EsiOptions extends EsiTransformOptions {}
  export function processEsi(
    response: Response,
    options?: EsiOptions,
  ): Response;
  ```

- [ ] **Step 1:** Write failing tests: an `text/html` response with
      `<esi:include>` markup returns a new `Response` whose body, read to
      completion, has the fragment spliced in; a `Content-Type: application/json`
      (or `image/png`) response passes through with an **identical** body and no
      fragment fetch attempted (assert the fetch stub is never called); a
      plain-text response with no ESI markup at all is a byte-for-byte no-op;
      the returned response drops `Content-Length` but otherwise preserves the
      original headers verbatim (assert `cache-control`, if present on the
      input, survives unchanged — the design doc's explicit non-goal of forcing
      `max-age=0`).
- [ ] **Step 2:** Run tests — confirm failure.
- [ ] **Step 3:** Implement `esi.ts`: check `response.headers.get(
"content-type")` against a small textual-type allowlist (`text/html`,
      `text/plain`, `application/xhtml+xml`, matching on the MIME type only, not
      the charset parameter); if it doesn't match or `response.body` is `null`,
      return `response` (or a clone if the caller needs the original body
      preserved for reuse — check whether `Response` bodies here need cloning
      given they're consumed by piping) untouched; otherwise pipe
      `response.body` through `createEsiTransformStream(options)` and construct
      a new `Response(transformedBody, { status, statusText, headers })` with
      `Content-Length` deleted from the copied headers.
- [ ] **Step 4:** Write `index.ts` with the package doc comment (`@see
docs/superpowers/specs/2026-07-13-esi-design.md`) re-exporting
      `processEsi`, `EsiOptions`, `createEsiTransformStream`,
      `EsiTransformOptions`, `resolveFragment` (in case a consumer wants the
      fragment-fetch primitive standalone), `EsiToken`, `EsiTokenizer`.
- [ ] **Step 5:** Run tests — confirm pass; run
      `pnpm --filter @dwk/esi typecheck && pnpm --filter @dwk/esi build`.
- [ ] **Step 6:** Commit: `feat(esi): add processEsi public API`.
